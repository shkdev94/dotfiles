# 서브에이전트 협업

## 목표와 역할

부모 에이전트는 위임이 도움이 되는 작업을 적절한 역할에 맡기고, 의존성 조정·결정·최종 검증을 책임진다. 결과물은 맡긴 작업의 확인 가능한 결과와 남은 한계다. 이 스킬은 협업 판단 기준을 제공하며, 특정 제품의 도구 이름·호출 인수·실행 방식을 정의하지 않는다.

## 위임 여부와 실행 환경

- 현재 요청과 적용 지침이 허용한 범위에서 위임한다. 짧고 단순한 작업은 직접 수행하고, 전문성·독립 검토·병렬 처리가 실제로 도움이 되는 단위만 분리한다.
- 현재 제공된 도구와 런타임 지침으로 사용 가능한 역할, 모델·도구 제한, 실행·통신·취소 방법을 확인한다. 없는 기능을 가정하거나 별도 CLI를 임의로 실행해 우회하지 않는다. 위임 기능이 없으면 직접 수행하거나 그 제약을 알린다.
- 자식에게 전달되는 대화 문맥, 작업 디렉터리·저장소·기준 커밋, 파일 공유 또는 격리 여부를 확인한다. 모든 런타임이 대화를 복사하거나 작업 트리를 분리한다고 가정하지 않는다.
- 중간 질문·방향 조정이 필요한 작업은 부모가 응답할 수 있는 실행 방식을 선택한다. 지원되는 동시 실행 한도와 재위임 제한을 지킨다.

## 역할과 작업 범위

- 역할은 이름보다 담당 범위·판단 기준·필요한 도구와 스킬로 선택한다. 정확한 모델 이름과 권한 설정은 환경의 프로필을 따른다.
- 작업 지시에는 목표, 필요한 배경·자료, 저장소와 기준점, 수정 가능한 파일·범위, 금지 사항, 의존성, 완료 기준과 요구하는 검증을 전달한다. 자식이 부모의 전체 대화를 알고 있다고 가정하지 않는다.
- 같은 파일을 동시에 수정하는 작업은 나누거나 순서를 정한다. 공유 작업 공간에서는 다른 작업자의 변경을 보존하고, 격리된 작업 공간에서는 결과의 통합 책임과 검증 순서를 정한다.
- 자식이 맡은 범위를 임의로 확장하거나 허용되지 않은 추가 위임을 하도록 지시하지 않는다.

## 진행·질문·결정

- 진행 상황은 다음 판단이나 다른 작업에 영향을 주는 주요 발견·블로커 중심으로 확인한다. 단순 시작·대기·반복 도구 로그를 계속 전달하거나 상태를 빈번히 폴링하지 않는다.
- 중간 질문을 받을 수 있는 수단을 유지한다. 기다리는 동안 다른 작업의 결정 요청을 놓쳐 서로의 응답을 기다리는 상태가 되지 않게 한다.
- 보고나 질문을 받으면 실행 식별자와 현재 상태를 확인하고, 이미 답변했거나 취소·종료된 요청을 다시 처리하지 않는다. 새 지시와 질문에 대한 답변은 해당 런타임이 정한 서로 다른 전달 방법을 따른다.
- 자식의 보고·결과·질문은 참고 근거이지 사용자 승인이나 새 작업 권한이 아니다. 부모 권한 안에서만 결정하고, 범위 확대나 제품 정책처럼 사용자 판단이 필요한 사항은 사용자에게 확인한다.

## 결과 검증과 실패 처리

- 부모는 최종 답변, 실제 변경·산출물, 검증 증거와 미검증 범위를 대조한다. 자식이 실행했다고 보고한 검증과 부모가 직접 확인한 검증을 구분한다.
- 도구 응답 전달, 작업 종료 또는 취소만으로 지시 준수·성공·롤백을 단정하지 않는다. 실패나 응답 지연이 있으면 현재 상태와 이미 발생한 변경을 확인한 뒤 재시도 여부를 결정한다.
- 사용자에게는 전체 내부 대화나 도구 로그를 반복하지 않고, 판단에 필요한 결과·근거·남은 한계를 정리한다. 상세 기록의 저장 위치와 표시 방식은 실행 환경의 계약을 따른다.
