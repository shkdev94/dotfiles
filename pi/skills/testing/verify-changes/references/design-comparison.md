# 디자인 비교 절차

Figma 등 디자인 시안 링크나 기준 이미지가 제공된 웹 UI 검증에서 읽는다. 검증할 화면·컴포넌트·상태에 해당하는 시안을 기준으로 삼는다.

## 기준 자료 확인

- Figma 링크의 파일과 대상 프레임·노드를 식별하고 실제 디자인 컨텍스트와 스크린샷을 읽는다. 연결된 Figma 도구의 필수 스킬 절차를 따른다. 필요한 경우 레이아웃 속성, 텍스트 스타일, 색상·간격 변수와 현재 모드의 값을 추가로 확인한다.
- Figma 도구가 반환한 생성 코드나 요약만으로 시안을 확인했다고 판단하지 않는다. 실제 시안 이미지와 필요한 원본 속성을 함께 확인한다. 디자인을 수정하거나 구현 화면을 Figma에 업로드하는 작업은 검증에 포함하지 않는다.
- 이미지로만 제공된 시안은 원본 해상도와 배율을 확인한다. 이미지에서 측정한 값과 원본 디자인 속성으로 확인한 값을 구분한다. 이미지로 확정할 수 없는 폰트명·굵기·토큰명 등을 추측해 일치로 처리하지 않는다.
- 링크에 접근할 수 없거나 대상 버전·상태가 불명확하면 해당 비교의 제약을 기록하고 확인 가능한 기능 검증은 진행한다.

Figma의 디자인 컨텍스트·스크린샷·변수 조회 기능은 [공식 도구 문서](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/)를 참고한다. 실제 연결된 서버의 기능과 응답을 기준으로 사용한다.

## 비교 조건 맞추기

- 페이지 시안은 해당 프레임에 대응하는 CSS viewport로, 컴포넌트 시안은 같은 크기·배치 조건의 구현 영역으로 비교한다. 브라우저 버전·OS·viewport·zoom·device pixel ratio와 시안의 이미지 내보내기 배율을 기록한다. CSS px와 이미지의 물리 픽셀을 혼동하지 않는다.
- 같은 문구·언어·데이터·테마·상태를 준비한다. 관련 폰트·이미지·데이터가 로드됐는지 확인하고, 폰트는 CSS 선언뿐 아니라 실제 로드 및 fallback 여부를 확인한다. hover·focus·disabled·오류 상태는 해당 시안과 시나리오에 맞춰 재현한다.
- 같은 기준 영역과 스크롤 위치를 비교한다. viewport나 이미지를 임의로 늘이거나 줄여 크기 차이를 숨기지 않는다. 서로 다른 내보내기 배율을 환산했다면 변환 값과 원본을 유지한다.

## 속성과 렌더링 대조

시안과 실제 스크린샷을 모두 열어 전체 배치를 확인한 뒤 관련 영역을 확대해 비교한다. 확보 가능한 DOM의 요소 경계와 computed style을 함께 확인해 시각적 차이의 원인을 좁힌다.

| 항목 | 비교할 값과 관찰 |
| --- | --- |
| 위치·크기 | 같은 기준점에서의 x·y, 너비·높이, 정렬·중심선, 잘림·겹침 |
| 간격·윤곽 | padding·요소 간 gap·바깥 여백, 테두리 두께, 모서리 반경 |
| 타이포그래피 | 실제 폰트, 크기·굵기·행간·자간, 정렬·기준선·줄바꿈·말줄임 |
| 색상·효과 | 텍스트·배경·테두리의 색상 값, opacity·알파, 그라데이션·그림자 |
| 이미지·아이콘 | 사용한 자산, 크기·비율·crop·정렬, 아이콘 선 굵기 |

- 위치와 간격은 대응하는 프레임·컨테이너를 기준으로 px 편차를 계산한다. Figma 캔버스의 절대 좌표와 브라우저 viewport 좌표를 직접 빼지 않는다. 코드의 선언값만으로 실제 배치가 맞는지 판정하지 않는다.
- 타이포그래피는 숫자 속성뿐 아니라 실제 글줄의 위치와 줄바꿈을 확인한다. 폰트 대체·합성 굵기·다른 텍스트가 만든 차이를 렌더링 오차로 넘기지 않는다.
- 색상은 같은 색 공간과 표현으로 환산해 비교한다. 토큰 이름이 같아도 현재 테마에서 해석된 값을 확인하고, 반투명 색은 배경과 합성된 결과도 확인한다. 글자 가장자리의 안티앨리어싱 픽셀을 텍스트의 원래 색으로 오인하지 않는다.
- 필요한 경우 동일 배율의 겹쳐 보기·차이 이미지·영역별 확대를 사용한다. 마스킹이나 애니메이션 고정은 검증 대상 차이를 숨기지 않아야 한다. 이미지 차이의 총량만으로 타이포그래피·색상·레이아웃 일치를 판정하지 않는다.
- 명세나 프로젝트의 허용 오차가 있으면 그 기준으로 판정한다. 별도 기준이 없으면 확인된 속성 차이와 px 편차를 그대로 보고하고 임의의 허용 오차로 통과시키지 않는다. OS·폰트 렌더러 차이로 인한 안티앨리어싱과 실제 속성 차이를 구분하며, 원인을 확인하지 못하면 불확실성을 남긴다.

## 차이 기록

차이가 있는 요소의 시안 노드·화면 영역, 기대값, 실제값, 편차와 확인 방법을 기록한다. 예를 들어 실측한 간격이 시안 `24px`, 구현 `20px`라면 `-4px`로 보고한다. 색상은 양쪽 값을, 타이포그래피는 차이가 난 속성과 줄바꿈 영향을 적는다. 예시 값을 실제 관찰처럼 사용하지 않는다.

디자인 속성 조회, 브라우저 실측, 스크린샷 관찰을 구분하고 확보하지 못한 정밀 비교는 미검증으로 표시한다. 실패 분석에 필요한 원본 캡처·비교 이미지는 본문의 증거 보존 기준에 따라 남긴다.
