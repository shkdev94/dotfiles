# 개발 작업 지침

- 사용자에게 한국어로 진행 상황과 결과를 설명한다.
- 작업할 저장소의 AGENTS.md, 요구사항과 기존 코드의 관례를 먼저 확인한다.
- 새 Node.js/TypeScript 기반 TUI를 구현할 때는 Ink(React)를 기본 UI 구성 방식으로 사용한다. 탭, 선택·검색창, 설정 화면, 상태 표시 등 TUI 전반에 적용하며, 기존 프로젝트에 정해진 TUI 스택이나 사용자 요구사항이 있으면 이를 먼저 따른다.
- Pi 확장에 Ink UI를 삽입할 때는 Pi의 컴포넌트·입력·수명 주기 계약에 연결한다. Ink의 renderToString으로 얻은 화면을 render(width)에 전달할 수 있지만, 이 모드의 터미널 입력·포커스 훅은 동작하지 않으므로 입력과 상태 갱신은 어댑터에서 처리한다. 최종 터미널 출력은 Pi가 관리하고, 별도의 Ink 앱을 만들 때는 Ink가 관리한다.
- 작업에 맞는 스킬의 SKILL.md를 read 도구로 읽고 적용한다. 명시 호출은 /skill:<name>을 사용한다. 스킬의 보조 파일은 해당 스킬 디렉터리를 기준으로 읽는다.
- 웹 검색·URL 읽기가 필요하면 pi-web-access의 `web_enable`로 도구를 활성화한다. 검색은 `web_search`를 사용하고 검색 경로 설정이 적용되도록 `provider` 인수를 생략한다. URL 본문은 `fetch_content`로 읽는다.
- Figma 작업에는 `figma-remote` MCP 서버를 우선 사용한다. `figma` 서버는 Figma Desktop의 로컬 연결이다.
- 실제 확인한 사실과 추론을 구분하고, 실행하지 않은 검증을 성공으로 보고하지 않는다.
- 사용자와 다른 에이전트의 변경을 보존한다. 커밋·푸시·PR 작성은 사용자 요청에 포함된 경우 수행한다.
- 위임이 필요한 작업에는 pi-subagents의 subagents_enable과 subagent 도구를 사용하고, implementer, reviewer, review_fixer, issue_writer 역할을 사용한다. 동시에 실행하는 하위 에이전트는 최대 5개로 유지하고, 담당 범위와 완료 기준을 명시한다.
- reviewer는 프로젝트의 코드나 설정을 수정하지 않고 요청 범위의 리뷰를 수행한다. 코드나 설정 변경이 필요한 검증은 주 에이전트에 근거와 필요한 절차를 전달한다.
- 권한이 이미 주어진 작업은 완료까지 진행한다. 인증·제품 정책처럼 사용자의 입력이 필요한 사항만 질문한다.
