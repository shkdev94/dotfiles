# PR 연결과 GitHub 이슈 종료

GitHub 이슈를 참조하는 PR을 작성·갱신할 때 적용한다. 다른 플랫폼의 요구사항에는 원본 링크와 해당 플랫폼·프로젝트의 규칙을 사용하며 GitHub 이슈 번호나 종료 규칙으로 바꾸지 않는다.

## 연결 문구

이슈 본문과 관련 댓글의 완료 기준, 이번 변경과 실제 검증 결과를 확인한다. 연결된 이슈가 없으면 문구를 생략하고, PR 작성을 위해 이슈를 새로 만들지 않는다.

- **`Closes #번호`**: 이 PR의 병합으로 이슈 요구사항과 필수 검증이 모두 충족될 때 사용한다. 이슈 전체를 해결하는 단일 PR이나 이미 병합된 선행 작업과 이번 변경으로 완료되는 마지막 PR에 적용한다. 선택적인 개선이 남거나 리뷰·병합을 기다린다는 이유만으로 `Refs`로 바꾸지 않는다.
- **`Refs #번호`**: 일부만 구현하여 필수 작업이 남거나, 해결 대상이 아닌 관련 배경으로 참조할 때 사용한다. 남은 요구사항이나 참조 이유를 함께 기록한다. 완료 여부를 확인하지 않았다는 이유로 기본값처럼 사용하지 않는다.
- PR과 같은 저장소의 이슈에는 `#번호`를, 다른 저장소의 이슈에는 `owner/repo#번호`나 지원되는 전체 URL을 사용한다. 실제 호스트·저장소·이슈를 확인하고 번호를 임의로 변환하지 않는다.
- 이슈마다 완료 범위를 따로 판단한다. 예를 들어 `Closes #123`과 `Refs #456`을 함께 적을 수 있다. PR 생성·갱신 전에 각 문구가 실제 범위와 일치하는지 확인한다.

## 병합과 종료 상태

- 기본 브랜치 이외를 대상으로 하는 PR은 종료 키워드만으로 병합 시 이슈가 자동 종료된다고 가정하지 않는다. 완료 의미를 숨기려고 `Refs`로 바꾸지 말고, 기본 브랜치로 통합할 때 base와 종료 문구를 확인하는 등 필요한 후속 조치를 기록한다.
- stacked PR은 단계별 완료 범위와 실제 base를 확인한다. 선행 변경을 합쳐도 필수 작업이 남으면 `Refs`를 사용하고, 해당 단계까지 합쳐 이슈가 완료되면 `Closes`를 사용할 수 있다. 마지막 단계라는 이유만으로 전체 변경이 기본 브랜치에 통합됐다고 판단하지 않는다.
- 선행 PR 병합 후 후속 PR이 기본 브랜치를 대상으로 하게 되면 base와 종료 문구를 다시 확인한다. 별도의 통합 PR을 만들면 이슈를 완료하는 통합 PR에 종료 문구를 반영한다.
- PR 생성, 구현 완료, 기본 브랜치 통합과 이슈 종료는 각각 확인한다. 자동 종료되지 않은 이슈는 필요한 조치를 결과에 기록하고, 직접 종료는 사용자 요청이나 적용되는 워크플로 규칙이 있을 때 수행한다.
