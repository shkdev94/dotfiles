# 읽기 좋은 Excalidraw 작성

독자가 흐름과 관계를 쉽게 따라갈 수 있고, 사용자가 이후에도 요소를 옮기고 수정하기 편한 `.excalidraw` 파일을 만든다. 기존 파일을 정리할 때는 사용자의 내용·의미·스타일을 출발점으로 삼는다.

이 스킬은 작성과 정리의 판단 기준이다. 별도 패키지·브라우저·렌더러 설치를 요구하지 않는다. 결과물은 편집 가능한 `.excalidraw`이며, PNG 내보내기나 이미지 검증은 사용자가 요청하거나 이미 이용 가능한 환경에서 도움이 될 때 선택한다.

## 내용과 읽는 순서

- 먼저 그림이 설명하는 질문, 시작점, 핵심 관계와 읽는 방향을 파악한다. 기존 그림에서는 배치를 바꾸기 전에 요소와 연결 관계를 확인한다.
- 순차 흐름은 왼쪽에서 오른쪽 또는 위에서 아래로, 계층은 트리로, 병렬 책임은 레인으로 배치한다. 비교는 같은 기준선에 나란히 둔다. 내용이 같은 구조라면 표현도 반복해서 독자가 패턴을 익힐 수 있게 한다.
- 개요와 상세가 서로 방해하면 영역을 나누고 제목을 붙인다. 전체를 이해하는 데 필요한 연결은 영역 사이에서도 추적할 수 있게 유지한다.
- 정리 요청에서는 사실·조건·방향·항목을 임의로 없애거나 추가하지 않는다. 기술 명칭과 관계는 제공된 자료나 코드에 맞춘다. 설명에 필요하지 않은 코드·JSON 예시를 의무적으로 넣지 않는다.

## 배치·정렬·여백

- 관련 요소를 가까이 두고, 다른 주제 사이에는 더 넓은 여백을 둔다. 그룹 내부 간격과 그룹 사이 간격을 구별한다.
- 같은 행은 위쪽이나 세로 중심, 같은 열은 왼쪽이나 가로 중심처럼 하나의 기준으로 정렬한다. 크기가 다른 도형의 균등 배치는 중심 간격보다 도형 가장자리 사이의 여백을 기준으로 판단한다.
- 같은 역할의 요소에는 비슷한 크기와 스타일을 적용하되, 긴 내용까지 작은 고정 상자에 맞추지 않는다. 먼저 문장을 다듬거나 줄을 나누고 필요한 공간을 확보한다.
- 도형 안에는 텍스트 여백을, 도형 사이에는 연결선과 라벨이 지나갈 공간을 남긴다. 제목도 본문과 구분되는 여백을 갖게 한다.
- 기존 기준이 없다면 다음 값을 출발점으로 삼고, 내용과 실제 표시 크기에 맞춰 조정한다. 픽셀 수치를 지키기 위해 기존 레이아웃을 바꾸지는 않는다.

| 항목 | 시작 기준 |
| --- | --- |
| 도형 내부 여백 | 16–24px 정도 |
| 이웃 도형 사이 여백 | 48–80px 정도, 연결 라벨이 길면 더 넓게 |
| 영역 사이 여백 | 도형 사이 여백보다 크게 |
| 정렬 단위 | 8px 또는 16px 등 일관된 단위 |

- 한 화면에 넣기 위해 모든 요소와 글자를 축소하지 않는다. 정보가 많으면 자연스러운 주제별 영역으로 나누고 개요에서 상세로 읽게 한다.

## 텍스트와 시각적 위계

- 제목·본문·주석의 크기 차이를 일정하게 유지한다. 새 그림은 본문 20px 안팎, 제목은 그보다 크게 시작할 수 있다. 실제 용도에서 읽을 수 있는 크기를 우선한다.
- 노드 이름은 짧고 구체적으로, 설명은 가까운 별도 텍스트로 둔다. 긴 문단은 왼쪽 정렬, 짧은 도형 라벨은 가운데 정렬을 우선 검토한다.
- 한글·영문·숫자가 섞인 텍스트 폭을 글자 수만으로 확정하지 않는다. 사용하는 글꼴에 맞춰 여유를 두고, 명칭과 조건이 잘리지 않게 한다. 상자에 맞추려고 글자 크기부터 줄이지 않는다.
- 글꼴·선 굵기·모서리·손그림 정도는 같은 역할끼리 일관되게 유지한다. 기존 손그림 스타일을 정돈한다는 이유만으로 직선 스타일로 바꾸지 않는다.
- 중립색을 기본으로 두고 소수의 강조색을 의미에 맞게 쓴다. 같은 의미에는 같은 색을 쓰고, 상태나 분기는 글자·도형·선 형태로도 구별한다.
- 컨테이너는 시스템 경계·책임·단계 등 묶음의 의미가 있을 때 사용한다. 제목이나 간단한 주석에는 테두리 없는 텍스트를 활용한다. 장식용 상자와 중첩을 늘리지 않는다.

## 연결선과 라벨

- 주요 흐름이 한 방향으로 이어지도록 먼저 노드를 배치한 뒤 연결한다. 선 교차가 많으면 노드 순서와 영역 배치를 먼저 조정한다.
- 연결선이 관련 없는 도형이나 글자를 통과하지 않도록 빈 공간으로 경로를 잡는다. 꺾임과 우회를 줄이고, 교차가 연결 지점으로 오해되지 않게 한다.
- 화살표 끝은 대상 도형의 경계에 명확히 닿거나 작은 간격을 두게 한다. 상자 내부나 이름 위에 화살촉을 놓지 않는다.
- 조건 분기의 라벨은 분기점 가까이에, 그 외 라벨은 해당 선의 여유 있는 구간에 둔다. 어느 선을 설명하는지 모호하지 않게 한다.
- 되돌아가는 흐름은 주 흐름 바깥쪽으로 돌린다. 선이 겹친다는 이유로 실제 관계를 삭제하거나, 의미가 다른 여러 연결을 하나로 합치지 않는다.
- 편집 가능한 연결을 위해 화살표를 대상 도형에 바인딩한다. 단순 구분선에는 화살촉을 붙이지 않는다.

## 묶음과 편집 가능성

- 함께 이동해야 하는 복합 요소는 그룹으로 묶고, 서로 독립적으로 편집할 영역까지 한 그룹으로 묶지 않는다.
- 프레임은 이름 있는 영역이나 장면을 나눌 때 사용한다. 프레임 밖으로 나간 자식 요소가 잘리지 않도록 영역 크기와 소속을 함께 확인한다.
- 기존 파일을 옮기거나 크기를 바꿀 때 연결된 텍스트·화살표·그룹 구성원도 함께 조정한다. JSON 좌표를 직접 바꾸면 편집기의 자동 이동이 실행되지 않는다는 점을 고려한다.
- 내용이 없는 장식과 불필요한 중첩을 줄이되, 링크·이미지·주석처럼 사용자가 담은 정보는 정리 과정에서 보존한다.

## JSON을 직접 작성·수정할 때

- 파일 전체를 먼저 읽고 `type`, `version`, `source`, `elements`, `appState`, `files` 구조를 유지한다. 기존 파일의 요소 ID와 무관한 속성, 이미지 데이터, 링크, 사용자 데이터를 보존한다. 새 ID는 중복되지 않게 만든다.
- 간략한 요소 생성 API 예시와 저장 파일 형식을 혼동하지 않는다. 기존 유효한 요소나 해당 버전의 형식을 참고한다. 불확실한 필드는 아래 공식 자료에서 확인하며, 특정 라이브러리 설치를 전제로 하지 않는다.
- 도형에 속한 텍스트의 `containerId`와 도형의 `boundElements`를 서로 일치시킨다. 화살표의 `startBinding`·`endBinding`도 대상의 `boundElements`와 맞춘다. 삭제되었거나 존재하지 않는 요소를 참조하지 않게 한다.
- 텍스트 내용을 바꾸면 `originalText`와 표시용 `text`가 같은 내용을 담도록 갱신한다. 자동 줄바꿈으로 두 값의 줄 구성이 달라질 수 있다. 글꼴·크기·줄바꿈을 바꾸면 텍스트 치수와 위치도 함께 확인한다.
- 선의 `points`는 요소의 `x`, `y`를 기준으로 한 로컬 좌표다. 회전된 요소는 `angle`도 고려한다. 이동과 경로 변경을 구분하고, 꼭짓점·크기·바인딩이 서로 어긋나지 않게 한다.
- `groupIds`와 `frameId`의 기존 관계를 유지한다. `elements`를 ID나 좌표로 무작정 정렬하지 않는다. 배열 순서는 겹침에 영향을 주며, 프레임 자식은 해당 프레임보다 앞에 와야 한다. 순서를 바꾸면 기존 `index`와의 일관성도 확인한다.

## 확인과 전달

- 기존 파일은 수정 전후의 내용과 연결 관계를 비교한다. 의도하지 않은 누락, 연결 방향 변경, 이미지·링크 손실이 없는지 확인한다.
- 이용 가능한 JSON 파서로 문법을 확인하고, ID 중복·없는 대상 참조·바인딩 불일치를 점검한다. 좌표와 치수로 예상 겹침·여백·선 경로를 검토하되, 의도적인 포함 관계를 겹침 오류로 취급하지 않는다.
- 화면 확인 수단이 이미 있으면 전체 흐름과 주요 구간의 글자·연결선을 확인한다. 이 스킬을 실행하기 위해 렌더러 설치나 PNG 생성을 필수 단계로 추가하지 않는다. JSON 검사만으로 시각적 품질까지 검증했다고 말하지 않는다.
- 결과 파일과 주요 정리 내용을 간단히 전달한다. 화면으로 확인하지 못했다면 그 사실을 밝히고, 문법·참조 검사와 시각적 검증을 구분한다.
