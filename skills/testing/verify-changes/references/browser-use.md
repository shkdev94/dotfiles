# browser-use 실행과 세션 관리

웹 UI를 검증할 때 읽는다. 설치된 browser-use MCP의 도구 목록과 인자 스키마를 먼저 확인한다. 버전마다 지원 범위가 다를 수 있으므로 아래 도구 이름을 실제 제공 목록과 대조한다.

## 실행 환경과 프로필

- 로컬 MCP 서버는 `browser-use --mcp`로 실행하며, headless 검증에는 서버 시작 환경으로 `BROWSER_USE_HEADLESS=true`를 전달한다. 실제 브라우저 실행 파일과 headless 설정이 적용됐는지 확인한다. 이미 실행된 서버·브라우저에는 셸 환경 변수 변경이 소급 적용되지 않는다.
- MCP와 일반 CLI가 같은 브라우저·프로필에 연결된다고 가정하지 않는다. 세션의 URL·탭·프로필·실행 모드를 확인한 뒤 검증한다. 기존 사용자 브라우저에 연결한 경우에는 그 세션의 실제 실행 모드를 보고한다.
- 프로필은 필요한 상태에 맞춰 선택한다. 초기 상태를 확인할 때는 임시 프로필을, 로그인·쿠키를 유지해야 할 때는 재사용 프로필을 사용할 수 있다. 사용자 세션 자체가 검증 대상이면 해당 세션을 사용한다. headless 여부와 프로필 재사용 여부는 별도로 결정한다.
- viewport와 배율은 요구사항과 디자인 시안에 맞춘다. 도구에 크기 변경 기능이 없다면 설치된 버전의 브라우저 프로필 설정을 확인해 세션 시작 시 적용한다. 설정값만 믿지 않고 캡처 메타데이터나 사용 가능한 DOM 측정으로 실제 크기를 확인한다.

## 조작과 관찰

1. `browser_navigate`로 대상 화면에 이동하고 `browser_get_state`로 현재 탭과 조작할 요소를 확인한다.
2. `browser_click`·`browser_type` 등으로 시나리오를 실행한다. 화면이 바뀌면 상태를 다시 읽어 현재 요소 인덱스를 사용한다. 이전 화면의 인덱스를 재사용하지 않는다.
3. 화면의 준비 조건과 기대 결과를 확인한다. 클릭 도구의 성공 응답은 업무 동작의 성공을 뜻하지 않는다. 페이지 상태·필요한 HTML·후속 상태로 결과를 대조한다.
4. `browser_screenshot`으로 필요한 영역을 촬영하고 반환된 이미지를 실제로 확인한다. 파일로 저장했다면 이미지 보기 도구로 연다. 전체 페이지 캡처 여부와 viewport·배율·스크롤 위치를 함께 기록한다.

`browser_get_html`은 HTML 조회이며 computed style이나 요소 좌표의 실측을 대신하지 않는다. 설치된 MCP에 DOM/CSS 측정 기능이 없다면 같은 세션에서 사용할 수 있는 읽기 전용 측정 수단을 확인한다. 확보하지 못한 실측값은 미검증으로 남긴다. LLM 기반 콘텐츠 추출 결과도 수치 측정의 근거로 삼지 않는다.

## 종료

세션 목록에서 이번 검증에 사용한 세션을 식별하고, 새로 만든 세션은 `browser_close_session` 등 제공되는 종료 도구로 정리한다. 여러 세션을 공유할 수 있으므로 전체 종료를 무조건 호출하지 않는다. 재사용한 세션에서는 이번 작업에서 만든 탭만 정리하고, 기존 로그인·쿠키·프로필을 삭제하지 않는다. 임시 프로필을 만들었다면 해당 브라우저가 종료된 뒤 그 경로만 정리한다.

MCP 실행 인자와 headless 환경 변수의 공식 정의는 [browser-use MCP manifest](https://github.com/browser-use/browser-use/blob/main/browser_use/mcp/manifest.json)에 있다. 실제 사용 시에는 설치 버전의 정의를 우선한다.
