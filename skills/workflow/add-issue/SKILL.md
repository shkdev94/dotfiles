# 이슈 추가

## 목표와 역할

다른 스킬이나 앞선 대화에서 충분히 검토한 결과를 받아, 이후 담당자가 이해하고 작업할 수 있는 이슈로 정리해 등록한다. 이미 확정된 문제·목적·범위·결정을 충실하게 옮기는 것이 이 스킬의 역할이다.

- 입력은 현재 대화의 검토 결과, 사용자가 지정한 문서·파일·링크, 또는 다른 스킬이 작성한 인계 내용이다. 특정 검토 스킬이나 고정된 입력 형식을 요구하지 않는다.
- 제공된 검토 결과를 기준으로 작성한다. 버그 재현, 근본 원인 재검증, 기본 브랜치 fetch와 비교, 런타임 조사, 대안 설계, 테스트 실행을 등록의 전제 조건으로 요구하지 않는다.
- 등록 대상 식별, 적용 지침과 이슈 양식 확인, 중복 검색, 메타데이터 확인, 등록 결과 조회 등 기록에 필요한 읽기 작업은 수행한다.
- 별도의 조사나 기록 전담 서브에이전트를 필수로 요구하지 않는다.
- 검토되지 않은 사실이나 결정을 만들어 넣지 않는다. 제공된 증거, 확정된 결정, 제안, 미해결 사항을 구분한다. 다른 스킬의 검증 결과는 그 출처와 함께 기록하며 직접 검증했다고 표현하지 않는다.
- 실제 코드 수정, 의존성 변경, 커밋, 푸시, PR 생성, 배포는 수행하지 않는다. 이슈의 구현 범위와 테스트 항목은 향후 담당자를 위한 내용이다.

## 입력 정리

사용자가 지정한 자료와 현재 대화에서 관련 검토 결과를 먼저 읽고, 다음 내용을 작업별로 추출한다.

- 어떤 문제를 해결하거나 어떤 결과를 달성하려는지
- 영향을 받는 영역과 현재 상태
- 검토에서 합의한 작업 범위와 제외 범위
- 제공된 증거, 재현 절차, 코드 참조, 관련 문서
- 확정된 수용 기준과 검증 방법
- 의존 작업과 명시된 미해결 사항

모든 항목을 일률적으로 필수 입력으로 요구하지 않는다. 작업 규모에 맞게 작성하고, 자료에 없는 세부 구현이나 테스트를 새로 설계하지 않는다. 확정된 결과를 의미 변경 없이 수용 기준으로 풀어 쓰는 것은 허용한다.

검토 결과가 보이지 않으면 위치나 내용을 요청한다. 등록 대상이나 핵심 목적·범위를 확정할 수 없거나 자료가 서로 모순되면 필요한 사항만 질문하고 해당 항목의 등록을 보류한다. CI 등 비대화형 환경에서는 응답을 기다리지 않고 등록을 보류한 항목의 부족한 자료·영향·필요한 결정을 반환하며, 독립적으로 등록 가능한 항목은 진행한다. 직접 조사를 시작하거나 다른 검토 스킬을 자동 실행하지 않는다. 핵심 작업을 설명하는 데 지장이 없는 미해결 세부사항은 명시해서 기록할 수 있다.

## 작업 분리

사전 검토의 작업 단위를 우선 사용한다. 독립적으로 구현하고 완료 여부를 판단할 수 있는 항목은 각각 이슈로 정리한다. 하나의 결과를 위한 밀접한 변경은 묶고, 원래 범위를 확대하지 않는다. 특정 수정이나 기능에 딸린 문서 변경은 해당 이슈의 작업 범위에 포함한다.

이슈 유형·분류와 필수 필드는 해당 플랫폼 스킬과 프로젝트 규칙에 따른다. 이 스킬에서 공통 유형을 정하거나 플랫폼의 필드로 자동 매핑하지 않는다.

## 플랫폼 작업

- 사용자 요청, 제공된 링크, 대화와 프로젝트 설정에서 등록 대상을 파악한다. 이미 알 수 있는 대상을 별도 입력으로 다시 요구하지 않는다. 코드 저장소의 호스팅 서비스만으로 이슈 등록 플랫폼을 정하지 않는다.
- 조회·검색·등록·첨부와 메타데이터 처리는 해당 플랫폼 스킬을 적용한다. GitHub 이슈 작업에는 [manage-github-issue](../../github/manage-github-issue/SKILL.md)를 사용한다.
- 플랫폼 스킬이 없으면 사용 가능한 도구와 프로젝트 지침으로 처리할 수 있는지 확인한다. 접근 수단이나 필수 규칙을 확인할 수 없으면 작성한 초안과 부족한 정보를 반환하며, 다른 플랫폼에 대신 등록하지 않는다.

## 이슈 작성 기준

대상 프로젝트의 적용 지침과 이슈 양식을 따른다. 별도 형식이 없으면 간결한 제목을 사용하고, 영역이 명확하면 `<영역>: <설명>`으로 작성한다. 본문은 아래 항목 중 작업에 필요한 내용만 포함한다.

```markdown
## 요약
해결할 문제 또는 달성할 결과와 그 이유.

## 배경 및 검토 결과
현재 상태, 제공된 증거, 검토에서 확정된 결정과 근거.
동작 오류를 다루면 제공된 현재 동작과 기대 동작, 재현 절차, 확인된 원인을 포함한다.

## 작업 범위
수행할 작업과 보존해야 할 동작. 검토에서 정한 호환성·마이그레이션·문서화 등의 요구사항.

## 완료 기준
- 검토 결과를 바탕으로 완료 여부를 판단할 수 있는 조건.

## 검증 방법
사전 검토에서 제시한 테스트 또는 확인 절차와 기대 결과.
이미 수행한 검증과 앞으로 수행할 검증을 구분한다.

## 제외 범위
검토에서 명시적으로 제외한 작업.

## 관련 자료
관련 이슈, 문서, 코드, 검토 결과의 출처와 의존 작업.
```

- 안내 문구를 실제 내용으로 대체하고 불필요한 섹션은 생략한다. 미해결 사항이 있으면 별도 섹션에 명시한다.
- 원래 대화나 외부 자료를 읽지 않아도 목적과 작업 범위를 이해할 수 있게 핵심 내용을 본문에 옮긴다. 링크만 붙여 인계하지 않는다.
- 비밀정보·자격 증명·개인정보·고객 데이터는 제외하거나 가린다. 민감정보를 가리는 과정에서 핵심 의미가 사라지면 추측으로 대체하지 말고 필요한 설명을 요청한다.
- 제공된 근거보다 강하게 단정하거나, 누락된 조사·결정·검증이 완료되었다고 표현하지 않는다.
- 재현 상황이나 현재·기대 동작을 이해하는 데 도움이 되는 제공된 스크린샷은 해당 설명 가까이에 첨부한다. 첨부 전 민감정보 포함 여부를 확인하고 플랫폼이 지원하는 방식으로 반영한다. 로컬 경로를 첨부 링크로 쓰지 않는다. 기존 첨부 URL이 있으면 재사용하며, 스크린샷 확보를 위해 새로 재현하거나 스크린샷을 등록의 필수 조건으로 요구하지 않는다.
- 스크린샷에는 무엇을 보여주는지 짧게 설명하고 텍스트 재현 절차를 대체하지 않는다. 초안만 요청한 경우 업로드하지 않고 첨부 예정 파일을 표시한다. 업로드가 실패하면 첨부했다고 쓰지 않고 실패를 알리며, 텍스트만으로 이슈를 설명할 수 있으면 등록을 계속한다.

## 등록 절차

1. 입력 자료에서 작업별 제목과 본문을 정리한다.
2. 작업 맥락에서 등록 대상을 확인한다. 대상을 하나로 결정할 수 없으면 사용자에게 묻는다.
3. 해당 플랫폼의 접근 수단과 권한, 적용 지침·양식·필수 메타데이터를 확인한다.
4. 같은 문제 또는 동일한 목적과 범위를 다루는 진행 중인 이슈를 검색한다. 비슷한 키워드만으로 중복이라고 판단하지 않는다.
5. 중복이 없으면 이슈를 생성한다. 진행 중인 중복 이슈가 있으면 기존 내용을 보존하고 새 검토 결과가 보완하는 내용만 댓글 등 지원되는 방식으로 한 번 추가한다. 추가할 내용이 없으면 기존 이슈를 반환한다. 종료된 이슈는 관련 이력으로 연결하되, 사전 검토에서 현재 필요한 작업으로 정리한 항목은 새 이슈로 기록한다. 상태 해석과 재개 규칙은 해당 플랫폼과 프로젝트 지침을 따른다.
6. 생성 또는 댓글 추가 후 해당 기록을 다시 조회해 대상·제목·본문·적용 메타데이터와 URL을 확인한다. 첨부한 스크린샷은 반환된 첨부 URL이 본문에 반영됐는지 확인한다. 쓰기 응답이 불확실하면 먼저 등록 여부를 확인해서 중복 생성을 피한다.
7. 작업별 결과를 보고하고 종료한다. 이슈에 기록한 작업을 이어서 구현하지 않는다.

사용자가 등록을 요청했고 대상과 내용이 명확하면 별도의 최종 승인을 반복해서 요구하지 않는다. 초안만 요청했거나 계획 모드라면 쓰기를 수행하지 않고 대상·제목·본문·메타데이터를 제시한다. 이 스킬에서의 기록 승인은 구현까지 허용하지 않는다.

여러 항목은 순차 등록한다. 일부 항목의 정보가 부족하거나 등록이 실패해도 독립적인 나머지 항목은 처리한다. 결과에는 각 항목의 새 이슈 생성·댓글 보완·기존 이슈 반환·초안 작성·보류·실패 여부와 해당 URL을 포함하고, 보류나 실패 이유는 짧게 설명한다.

대상 코드와 기존 사용자 변경은 수정하지 않는다.
