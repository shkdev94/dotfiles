# 네이티브 의존성과 빌드

네이티브 모듈·폰트·권한·빌드 설정 또는 모노레포 패키지 배치를 바꿀 때 읽는다.

## 의존성과 autolinking

- 실제 앱 패키지, 공유 JS 패키지, 네이티브 코드를 포함하는 패키지를 구분한다. 앱이 직접 사용하는 모듈은 앱의 의존성에 선언하고 공유 패키지의 공개 계약에 맞게 dependency·peer dependency를 정한다.
- 네이티브 autolinking의 탐색 범위와 재귀 처리, Metro의 해석 방식은 React Native·Expo 버전과 설정에 따라 다르다. 무조건 앱의 `node_modules`만 탐색한다고 가정하지 않는다.
- hoisting으로 개발 환경에서 우연히 해석되는 상태에 의존하지 않는다. 실제 앱이 링크한 네이티브 모듈과 JS가 해석한 패키지를 확인한다.
- React·React Native·네이티브 모듈의 중복 설치와 버전 불일치를 lockfile과 사용하는 패키지 관리자의 조회 기능으로 확인한다. 모든 JS 의존성을 단일 버전으로 강제하지 않고 런타임·바이너리 호환성에 필요한 범위를 맞춘다.
- Expo 프로젝트는 SDK에 맞는 모듈 버전과 설치 방식을 따른다. 프로젝트 패키지 관리자와 lockfile을 유지하고 문제와 무관한 SDK·의존성을 일괄 갱신하지 않는다.

## 설정과 실행 환경

- 네이티브 디렉터리를 생성하는 방식인지, 직접 관리하는 방식인지 확인한다. config plugin·앱 설정이 원본인 프로젝트에서 생성 결과만 고치면 다음 생성 때 변경이 사라질 수 있다.
- 폰트·권한·엔타이틀먼트·플러그인 설정은 사용하는 빌드 흐름에 맞게 반영한다. 네이티브 설정과 JS에서 사용하는 이름·권한 요청 시점이 일치하는지 확인한다.
- 새 네이티브 모듈이나 설정이 Expo Go에 포함된 런타임에서 지원되는지 확인한다. 필요한 개발 빌드·재빌드를 수행하며 OTA 업데이트나 JS 재시작으로 네이티브 바이너리가 바뀐다고 가정하지 않는다.
- 기존 프로젝트의 생성·빌드 명령을 사용한다. 로컬 네이티브 변경을 지우는 clean·재생성을 문제 분석 없이 실행하지 않는다.
- 권한 거부·취소와 앱 복귀, 플랫폼별 API 차이를 처리한다. 한 플랫폼의 빌드 성공만으로 다른 플랫폼도 검증됐다고 보고하지 않는다.
