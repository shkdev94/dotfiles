# 변경 사항 커밋

## 목표와 역할

현재 변경 사항과 사용자가 지정한 범위를 입력받아 diff와 검증 결과를 확인하고, 논리적 단위로 커밋한다. 결과물은 실제 변경을 설명하는 커밋과 검증 결과이며, push가 요청에 포함되면 원격 반영까지 수행한다.

## 진행 방식

- 저장소 지침과 최근 커밋 관례, 현재 브랜치·upstream·staged·unstaged·untracked 상태를 확인한다. 명시적인 사용자·저장소 규칙이 있으면 아래 기본 형식보다 우선한다.
- diff를 읽고 요청된 변경 범위를 확정한다. 기존 staged 변경이나 다른 작업을 무조건 포함하지 않고 대상 파일·필요한 hunk만 stage한다. 비밀 값과 생성물을 새로 포함하지 않는다.
- 목적과 의존성에 따라 논리적 커밋 단위를 구성한다. 파일 수나 종류만으로 분할하지 않으며 관련 없는 변경을 섞지 않는다.
- 변경 범위에 맞는 검증과 저장소 필수 검사를 확인한다. 이미 실행한 검증은 이후 변경이 없다면 활용하고, 실행하지 않은 검증을 통과로 보고하지 않는다.
- staged diff를 최종 확인하고 커밋한다. hook 실패는 원인을 확인해 해결하며 임의로 검사를 건너뛰지 않는다. 명시적인 요청 없이 기존 커밋을 amend하거나 이력을 재작성하지 않는다.
- push까지 요청받았다면 대상 원격·브랜치를 확인하고 push한다. 거부되면 원인을 확인하고 강제 push로 우회하지 않는다.

## 커밋 메시지

작성 형식은 다음 우선순위로 결정한다. 실행 환경의 필수 제약은 준수한다.

1. 이번 작업에서 사용자가 명시한 지침
2. 적용되는 `AGENTS.md`, 기여 지침, 필수 템플릿과 설정
3. 최근 유사 작업 여러 건에서 확인되는 일관된 저장소 관례
4. 위 기준으로 정해지지 않은 항목에 대한 아래 기본 형식

관례는 단일 사례나 자동 생성된 기록만으로 단정하지 않는다. 대상 경로·작업 유형에 맞는 사례를 비교하고, 명시된 규칙과 충돌하면 명시된 규칙을 따른다. 형식·언어·분류 등 저장소에서 정한 항목을 스킬의 기본값으로 덮어쓰지 않는다.

커밋 메시지는 다음 형식의 한 줄로 작성한다.

```text
[type] - 한국어 변경 요약
```

- `feat`: 새로운 기능 추가
- `fix`: 버그 수정
- `hotfix`: 긴급 버그 수정
- `refactor`: 동작 변경 없이 구조 개선
- `chore`: 설정, 의존성, 유지보수
- `docs`: 문서 수정
- `style`: 동작 변경 없는 코드 스타일·포맷팅
- `release`: 배포 준비

하나의 커밋에는 하나의 논리적 변경을 담고 메시지는 해당 커밋의 실제 변경을 요약한다. `코드 수정`, `작업`, `변경사항 반영`처럼 모호한 표현을 피한다.

```text
[feat] - 조직 멤버 초대 기능 추가
[fix] - 검수 완료 후 수정 값 표시 오류 수정
[chore] - 이슈 구현 스킬 추가
```

## 결과 전달

생성한 커밋 SHA와 메시지, 검증 결과, 남은 변경을 한국어로 보고한다. push를 수행했다면 원격과 브랜치 및 성공 여부를 함께 알린다.

## 유용한 명령어

변수는 확인한 실제 값으로 채운다. 필요한 명령만 선택하고, 설치 버전과 저장소의 실행 규칙을 따른다.

```bash
# 범위와 staged 변경을 구분해 검토
git status --short
git diff --stat
git diff -- "$FILE_PATH"
git diff --cached
git log -5 --format='%h %s'
# 해당 파일만 stage; 일부 hunk만 대상이면 대화형 git add -p 사용
git add -- "$FILE_PATH"
git diff --cached --check
git diff --cached
# 검토한 메시지를 담은 파일로 커밋
git commit -F "$MESSAGE_FILE"
git show --stat --oneline HEAD
git status --short
# push까지 요청된 경우에만 실행
git push "$REMOTE" "$BRANCH"
```

`git add .`·`git add -A`를 기본값으로 쓰지 않는다. 메시지 파일의 첫 줄은 위 우선순위로 결정한 커밋 형식을 따른다. hook 실패를 `--no-verify`로 우회하거나 push 거부를 `--force`로 우회하지 않는다.
