# Figma 화면 구성

## 목표와 역할

대상 파일의 디자인 시스템을 재사용해 편집 가능한 화면을 구성한다. 결과물은 컴포넌트 인스턴스와 토큰으로 연결된 UI, 변경 ID와 화면 검증 결과다.

## 준비와 자산 탐색

`use_figma` 호출 전 [use-figma](../use-figma/SKILL.md)를 읽는다. 대상 파일이 없고 사용자가 새 파일 생성을 요청했다면 [create-figma-file](../create-figma-file/SKILL.md)로 만든 키를 사용한다.

1. 코드·설명에서 화면의 영역, 필요한 컴포넌트, 제품 글꼴과 이미지 출처를 확인한다. 글꼴을 임의로 Inter로 정하지 않는다.
2. 필요한 컴포넌트의 Code Connect 파일을 먼저 찾는다. 연결된 라이브러리 파일의 노드에서 실제 component key를 읽는다.
3. 미확인 컴포넌트는 대상 파일의 기존 화면과 인스턴스를 조사한다. 그래도 없는 항목만 라이브러리 검색으로 보완한다.
4. 검색 전에 `get_libraries`로 라이브러리와 페이지네이션을 확인한다. `search_design_system`은 검색어마다 하나의 의도를 담고, 필요한 `includeLibraryKeys`를 지정한다.
5. 컴포넌트 속성, 색상·간격·반경 변수, 텍스트·효과 스타일을 대응시킨다. 로컬 변수 조회가 비었다는 이유로 원격 변수를 무시하지 않는다.

자산 탐색과 가져오기 방법은 [디자인 시스템 재사용](references/design-system.md)을 읽는다. 디자인 시스템이 없거나 권한 때문에 확인할 수 없다면 확인된 범위와 부족한 항목을 구분한다.

## 화면 작성

- 확인한 component key로 가져온 인스턴스를 사용한다. 표시만 비슷한 박스를 만들거나 인스턴스를 바로 detach하지 않는다.
- 내부 레이아웃은 auto-layout으로 구성하고, 지원하는 컴포넌트 속성으로 텍스트·variant·아이콘을 설정한다.
- 웹 화면에 외부 이미지가 있다면 `generate_figma_design` 캡처를 같은 파일에 가져와 참조하거나 파일 안에 이미 존재하는 이미지 자산을 사용한다. `use_figma`가 외부 URL을 직접 가져올 수 있다고 가정하지 않는다.
- 이미지 캡처에서 얻은 `imageHash`를 실제 결과의 fill에 연결하고 비교한다. 캡처를 제거할 때는 이번 작업에서 만든 참조 노드의 정확한 ID만 사용한다.
- 새 재사용 컴포넌트가 필요한 부분은 [build-figma-library](../build-figma-library/SKILL.md)로 처리한다. 화면 한 개를 요청했다고 전체 디자인 시스템을 재구축하지 않는다.

## 확인과 전달

영역 단위로 반환된 ID·경계·개수를 확인하고 완성한 화면의 스크린샷을 원본과 비교한다. 이미지, 글꼴, 간격, 컴포넌트 상태와 잘림을 확인한다. 결과 링크와 변경 범위, 재사용한 디자인 시스템 및 해결하지 못한 차이를 보고한다.
