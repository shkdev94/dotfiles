# Figma 디자인 구현

## 목표와 역할

Figma의 구조·이미지·디자인 시스템 정보를 실제 프로젝트의 코드와 동작으로 옮긴다. 결과물은 수정된 코드, 로컬 정적 자산과 요청 범위의 검증 결과다.

## 디자인과 프로젝트 확인

1. URL의 파일 키와 노드 ID를 확인하고 대상 화면·상태를 정한다. 브랜치 URL에서는 브랜치 키를 사용한다.
2. `get_design_context`에 프로젝트 언어·프레임워크를 전달하고 디자인 스크린샷도 요청한다. 이미지가 반환되지 않으면 구현 전에 `get_screenshot`을 호출한다.
3. 응답이 `sparse`라고 표시되거나 정보가 부족하면 자식 ID를 스크린샷과 대응시켜 필요한 하위 노드를 다시 조회한다. 부족한 구조를 추측해 구현하지 않는다.
4. 프로젝트의 화면 위치, 기존 컴포넌트, 의존하는 디자인 라이브러리, 자산과 토큰을 읽는다. Code Connect가 연결한 컴포넌트는 정확한 노드에 대응시켜 재사용한다.

## 구현

- 반환된 코드는 시각적 구조의 자료다. 프로젝트의 레이아웃 방식, 상태 관리, 라우팅과 상호작용으로 옮긴다. 고정 좌표를 그대로 복사해 반응형 구조를 무너뜨리지 않는다.
- 기존 컴포넌트의 설정·조합으로 디자인을 표현할 수 있으면 이를 사용한다. 스타일 연결이 번거롭다는 이유로 새 마크업을 만들지 않는다.
- 정적 이미지와 SVG는 응답의 다운로드 절차에 따라 로컬 자산으로 저장한다. 임시 Figma URL을 제품 코드에 남기지 않는다. API나 props로 공급되는 이미지는 동적으로 유지한다.
- 디자인 스크린샷 자체를 화면 구현 자산으로 쓰지 않는다. 제공된 자산의 배치·비율을 보존하고 SVG의 원본 크기를 무조건적인 `100%` 스타일로 덮지 않는다.
- 애니메이션이 포함되면 [implement-figma-motion](../implement-figma-motion/SKILL.md), SwiftUI라면 [convert-figma-swiftui](../convert-figma-swiftui/SKILL.md)의 해당 방향을 함께 적용한다.

## 검증과 전달

요청한 화면·상태에서 렌더링 결과와 스크린샷을 비교한다. 각 정적 자산이 실제 파일로 존재하고 올바른 코드 위치·디자인 영역·렌더링 크기에 쓰였는지 확인한다. 버튼과 입력 등의 동작도 확인하며, 요청 밖의 기존 차이는 수정 범위를 넓히지 않고 기록한다.

구현한 범위, 검증 결과와 남은 제약을 보고한다. 도구 스키마가 지원하면 `skillNames`에 `implement-figma-design`을 전달한다.
