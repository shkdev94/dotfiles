# FigJam 다이어그램의 유형별 문법

| 표현할 내용 | 문법 | 확인할 제약 |
| --- | --- | --- |
| 처리 흐름·조건 분기 | `flowchart` | 노드·edge 라벨을 짧고 명확하게 쓰고 특수문자는 따옴표로 감싼다. |
| 서비스·저장소·큐의 구조 | `flowchart` | 계층·시스템 경계와 연결을 실제 구조에 맞추고 아키텍처 전용 옵션은 도구 스키마·공식 지침을 확인한다. |
| 참여자 사이의 시간순 호출 | `sequenceDiagram` | `Note`는 렌더링 과정에서 빠질 수 있으므로 중요한 주석을 여기에만 담지 않는다. |
| 테이블·키·카디널리티 | `erDiagram` | 실제 스키마에서 관계와 키를 확인한다. |
| 상태와 전이 | `stateDiagram-v2` | 상태, 전이 조건과 시작·종료를 구분한다. |
| 날짜·마일스톤·의존 일정 | `gantt` | 스타일이 제거될 수 있어 색상만으로 업무 의미를 전달하지 않는다. |

지원 문법의 세부 옵션은 일반 Mermaid와 다를 수 있다. 사용할 유형의 [공식 참고 문서](https://github.com/figma/mcp-server-guide/tree/172920731eedf414e9b22ae60017d9a5b6c9f81f/skills/figma-generate-diagram/references)에서 `flowchart.md`, `architecture.md`, `sequence.md`, `erd.md`, `state.md`, `gantt.md` 중 해당 파일을 읽는다. 모든 유형을 미리 읽지는 않는다.

시퀀스 주석이나 간트의 색 구분이 필요하면 기본 다이어그램을 생성한 뒤 `get_figjam`으로 ID를 확인하고 FigJam의 텍스트·sticky·section으로 보완한다. 추가 작업이 실패해도 이미 만들어진 다이어그램 링크와 남은 부분을 구분해 전달한다.

수정할 때는 반환된 파일 키를 재사용한다. 기존 파일의 노드 글꼴이나 위치를 바꾸는 작업은 다이어그램 재생성 옵션으로 처리할 수 있다고 가정하지 않는다.
