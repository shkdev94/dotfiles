# 좋은 React Native 코드 작성

## 목표와 역할

요구한 모바일 UI 동작을 구현하고 목록·입력·화면 전환이 실제 기기에서 안정적으로 동작하게 한다. React Native의 렌더링과 네이티브 실행 환경을 고려해 구조와 성능을 판단한다.

- 입력은 요구사항, 관련 화면·컴포넌트·네이티브 모듈, 지원 플랫폼과 현재 빌드 환경이다.
- 결과물은 요청 범위의 구현, 확인한 플랫폼·기기와 검증 결과, 빌드나 호환성에 영향을 주는 선택 근거다.
- 컴포넌트 합성·상태·Effect는 [write-good-react](../write-good-react/SKILL.md)의 공통 React 기준을 따른다. 웹 DOM·SSR·Next.js 전용 지침을 네이티브 화면에 적용하지 않는다.
- 기존 목록·이미지·내비게이션·스타일링 라이브러리를 먼저 활용한다. 이 스킬을 적용한다는 이유로 패키지를 추가하거나 전면 교체하지 않는다.

## 실행 환경부터 확인하기

- React Native·React 버전, Expo 사용 여부와 SDK, 지원 OS, 아키텍처 설정, JS 엔진, React Compiler와 애니메이션 라이브러리를 확인한다.
- Expo Go·개발 빌드·릴리스 빌드 중 실제 검증 환경을 구분한다. 네이티브 코드·설정 변경은 JS 새로고침만으로 반영되지 않을 수 있으므로 필요한 빌드를 확인한다.
- 앱과 공유 패키지의 의존성 선언, lockfile과 기존 플랫폼별 코드를 읽는다. 버전별 API·설정은 해당 공식 문서를 확인한다.

## 목록과 렌더링 비용

- 길거나 계속 늘어나는 목록은 프로젝트에서 사용하는 가상화 목록으로 구현한다. 작은 고정 콘텐츠까지 일괄 전환하거나 특정 목록 라이브러리를 필수로 삼지 않는다.
- 데이터의 정체성을 나타내는 안정적인 key를 사용한다. 재활용되는 셀에 이전 항목의 선택·입력·이미지 상태가 남지 않는지 확인한다.
- 행 안의 반복 정렬·포맷 생성·이미지 디코딩·넓은 상태 구독을 살펴본다. 계산과 구독 범위를 줄이고, `memo`와 참조 안정화는 비용과 소비자의 계약에 맞게 적용한다.
- 목록 성능을 바꿀 때는 [목록·이미지·스크롤 점검](references/list-performance.md)을 읽는다. 라이브러리별 옵션과 높이 추정을 서로 혼용하지 않는다.

## 애니메이션과 사용자 입력

- 매 프레임의 스크롤·제스처 값을 React state에 저장해 화면 전체를 갱신하지 않는다. 기존 애니메이션 시스템의 값과 파생 값으로 처리하고 React가 필요한 의미 있는 상태 변화만 전달한다.
- 같은 화면 결과를 낼 수 있으면 `transform`·`opacity` 중심으로 구성한다. 레이아웃 크기 변화가 필요한 동작을 단순 스케일로 바꿔 터치 영역·주변 배치가 어긋나게 하지 않는다.
- native driver·worklet·공유 값은 사용 버전의 지원 범위와 스레드 경계를 확인한다. 애니메이션 종료·중단·화면 이탈 때의 정리와 오래된 상태 참조를 점검한다.
- 일반 버튼은 기존의 접근 가능한 버튼·`Pressable`을 활용한다. 제스처 조합이 필요한 경우에만 제스처 전용 API를 선택하고 스크롤·뒤로 가기와의 충돌을 확인한다.
- 모션 감소 설정과 연속 입력, 중간 취소에도 상태가 일관되게 남는지 확인한다.

## 플랫폼 UI와 네이티브 경계

- 텍스트는 `Text` 안에 렌더링한다. 숫자·문자열을 조건으로 `&&`를 사용해 `0` 같은 값이 의도치 않게 자식으로 렌더링되지 않도록 명시적인 조건을 쓴다.
- 접근성 역할·레이블·상태, 터치 영역, 글자 크기 확대와 스크린리더 동작을 확인한다. 시각적 배치만으로 버튼이나 선택 상태를 표현하지 않는다.
- safe area와 키보드, 내비게이션 헤더·탭의 inset 소유자를 확인해 여백을 중복 적용하지 않는다. iOS 전용 스크롤 옵션을 Android의 해결책으로 가정하지 않는다.
- 화면 전환·모달은 기존 내비게이션 구조와 플랫폼 동작에 맞춘다. 현재 문제가 없는 내비게이터를 성능 일반론만으로 교체하지 않는다.
- 네이티브 모듈·폰트·권한·모노레포 의존성을 바꿀 때는 [네이티브 의존성과 빌드](references/native-boundaries.md)를 읽는다.

## 검증과 결과

- 관련 타입 검사·린트·테스트를 실행하고, 변경한 화면의 입력·로딩·오류·화면 이탈을 확인한다. 네이티브 설정 변경은 해당 플랫폼의 빌드와 런타임에서 검증한다.
- 플랫폼 공통 변경이면 iOS와 Android의 영향을 확인한다. 시뮬레이터·에뮬레이터·실기기 중 사용한 환경과 미확인 플랫폼을 명시한다.
- 성능은 가능하면 대표 기기의 릴리스 빌드에서 같은 시나리오로 비교한다. JS 작업, UI 프레임, 이미지·메모리 중 병목을 구분하고 개발 모드의 수치만으로 개선을 단정하지 않는다.
- 결과에는 변경한 동작과 필요한 재빌드, 실제 검증 결과를 보고한다. 실행 환경이 없으면 코드 검토 결과와 기기에서 확인할 항목을 구분한다.
